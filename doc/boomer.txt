1. INTRODUCTION                                                 *boomer-intro*

Boomer is a minimal chat buffer for coding agents. It speaks two protocols:

- `codex`: the Codex App Server protocol (`codex app-server`).
- `acp`: the Agent Client Protocol v1, used by GitHub Copilot CLI
  (`copilot --acp`), Gemini CLI, Claude Agent and other ACP agents (see
  |boomer-agents|).

Requires Neovim 0.12 or newer and an installed, authenticated agent. The
plugin loads lazily; nothing runs until the first command. Run
`:checkhealth boomer` to check the configured agents.

The agent runs with your environment, configuration and credentials, and
enforces its own sandbox. Boomer never adds auto-approval flags.

==============================================================================
2. USAGE                                                        *boomer-usage*

`:Boomer` opens a vertical split (see |boomer-window|) with a native
|prompt-buffer| and starts Insert mode at the end of the draft. Type after
`Prompt: ` and press <CR> to send; <S-CR> adds a line. The sent text stays in
the transcript as typed, after its `Prompt:` label, and replies stream above
the prompt, under `Agent:` labels, while you type. A picker opened while you
type in the prompt, such as for `/model` or a permission request, returns to
Insert mode once it is answered, after the last of several requests. <CR> on
a blank draft does nothing. A draft that cannot be sent or run now (a command
that cannot run yet) stays in the prompt, and a warning says why. CTRL-C
(Insert or Normal mode) cancels the active turn.

                                                        *boomer-queue*
A prompt sent while a turn runs, or while the chat starts or loads a session,
is queued; meanwhile the prompt's label, sign and text are grayed out
(`BoomerPromptBusy`, |boomer-highlights|). Queued prompts are shown as
`Queued:` lines above the prompt
(below it while the transcript is empty) and are sent one per turn, in order,
each once the previous turn ends; only then do they enter the transcript.
Plain prompts, agent commands and user `prompt` commands
(|boomer-user-commands|) are queued. Boomer's own commands are never queued:
they run at once, or warn if they cannot run now. CTRL-C and |boomer-/cancel|
cancel the turn and put the queued prompts back into the draft, before the
text being typed. <S-CR> in Normal mode sends a prompt now instead: it goes
ahead of the queued prompts and the turn is interrupted, so it is sent as
soon as the agent stops, followed by the rest of the queue. This includes
agent commands, such as Copilot's `/permissions`; Boomer's own commands run as
with <CR>. With a blank draft, it interrupts the turn for the next queued
prompt. A failed turn, an agent exit or a session that fails to
load also returns them to the draft.

- One chat per Neovim instance. Hiding the window keeps it; |:bdelete| or
  `:Boomer close` ends it. History is read-only; only the draft is sent.
- Turns have no timeout. A cancel waits for the agent to stop the turn; if
  the agent hangs, use `:Boomer close`.
- Switching sessions (`/new`, `/resume`) reuses the agent process and opens
  the session in a fresh buffer; the previous buffer is wiped. Loaded history
  shows user and assistant messages only.
- Each tool call is shown once as `[Tool: title]`.
- Permission requests show their details in the chat and are answered with
  |vim.ui.select()|. "Deny" is first, and dismissing the picker denies. If
  the picker closes without an answer (some pickers do this on <Esc>),
  `:Boomer` shows the request again.
- If the agent exits, the chat shows the exit code and the end of its stderr.
- Errors (`Error: ...`) and warnings (`Warning: ...`, such as a command that
  cannot run now) are written into the transcript. While the chat is hidden
  they are also given to |vim.notify()|, as are warnings without a chat.
  Like other output, a warning ends a streamed reply; the rest of it
  continues under a new label.
- The transcript is highlighted as Markdown with treesitter. Markers stay
  visible ('conceallevel' 0), so copied text is the original source.
                                                        *boomer-diffs*
- The files an agent changes, added, deleted, moved or edited, are shown as
  a fenced `diff` block of unified diff hunks, with `---`/`+++` headers
  (`/dev/null` for added and deleted files, paths relative to the chat's
  directory). The block follows the tool call, or precedes its permission
  request, so the change being approved is visible; edits that need no
  permission are shown too. Each file of a tool call is shown once. Blocks
  longer than `diff_lines` lines (|boomer-config|) end with
  `... N more lines`. They are highlighted like |diff-mode|: added and
  deleted lines get a line background, and the changed middle of a deleted
  line followed by its added replacement is highlighted on both (see
  |boomer-highlights|). Diffs are not shown in loaded history.
- One blank line always separates the prompt from the transcript. When the
  transcript does not end with one (such as while a reply streams), it is a
  virtual line (|nvim_buf_set_extmark()| `virt_lines`), not buffer text.

3. COMMANDS                                                  *boomer-commands*

                                                        *:Boomer*
:Boomer                 Open or focus the chat, starting the default agent.

:Boomer {command} [{args}]
                        Run {command}, one of the commands below. Commands
                        and their arguments complete with
                        |cmdline-completion|.

                                                        *boomer-slash*
The same commands can be typed in the prompt as `/command [args]`. Boomer
runs them itself; they are not sent to the agent. A draft is a command only
if it starts with `/name` followed by a space or the end of the draft, so text
such as `/etc/hosts is empty` is sent unchanged. Start the draft with `//` to
send text that begins with `/`.

In the prompt, 'omnifunc' (|i_CTRL-X_CTRL-O|) completes command names and
their arguments. The chat buffer's 'complete' option starts with `o`, so
|i_CTRL-N| and 'autocomplete' offer them too. For a menu while typing: >lua

    vim.api.nvim_create_autocmd('FileType', {
        pattern = 'boomer',
        command = 'setlocal autocomplete',
    })
<

Saved sessions are not completed; `/resume` without an ID picks one.

Commands that take an argument open a |vim.ui.select()| picker without one;
dismissing the picker does nothing (but see |boomer-/resume|). Commands
shown without an argument below (`/new`, `/usage`, `/help`, `/cancel`,
`/close`) warn if given one, and keep a typed draft.

                                                *boomer-command-results*
A command that runs is shown as the user's message, as typed and with the
argument it resolved to (`/model gpt-5` after a picker), however it was given:
typed, from |:Boomer|, <S-Tab> or the |boomer-api|. Its result follows. A
command that cannot run only warns. Results are system lines such as:

    `[Setting: model = GPT-5]`      a setting changed; named by its command
                                  (`model`, `effort`, `mode`, `permissions`)
    `[Session: new]`                |boomer-/new|
    `[Session: {title}]`            |boomer-/resume|: the session's title, or
                                  its ID
    `[Agent: {name}]`               |boomer-/agent|
    `[... (current)]`               `/resume` or `/agent` chose what is
                                  already open; the chat is kept and focused

`/new`, `/resume` and `/agent` open a fresh buffer: their result is its first
line (after loaded history), written once the session is ready, and their
line is not shown. Plain |:Boomer| writes no result.

/model [{model}]                                        *boomer-/model*
        Set the session's model. {model} matches a model ID or its name.
        Settings change at once, also during a turn; Codex applies them from
        its next turn. Codex lists its models when it starts. If the agent
        offers no such setting but has its own command of the same name, the
        line is sent to it.

/effort [{level}]                                       *boomer-/effort*
        Set the reasoning effort.

/mode [{mode}]                                          *boomer-/mode*
        Set the session mode, for agents that offer modes. {mode} matches a
        mode ID or its name, such as `agent` or `plan`. Copilot's `/plan`
        enters plan mode, and only `/mode agent` leaves it: the agent cannot
        leave it by itself. Codex offers `default` and `plan` (its
        experimental collaboration modes); like the model, the mode applies
        from the next turn. In plan mode Codex asks its questions as text.
        <S-Tab> in the chat switches to the next mode.

/permissions [{preset}]                                 *boomer-/permissions*
        Choose what the agent may do without asking. Codex offers the
        presets of its own `/permissions`:
          `read-only`     Read Only: read files; ask before edits and
                        commands (`on-request`, read-only sandbox).
          `auto`          Default: edit and run commands in the workspace;
                        ask for anything else (`on-request`,
                        workspace-write sandbox).
          `full-access`   Full Access: no sandbox and no approvals
                        (`never`, `dangerFullAccess`). Use with care.
        The preset applies to the next turn and later ones in this session;
        a new or loaded session starts with the agent's configured policy.
        If an ACP agent advertises its own `/permissions`, the line is sent
        to it, even if the agent also has a permissions setting; the
        choices in its hint complete the argument, and without one a picker
        offers them. Copilot offers `default`, `assisted`, `allow-all`
        (approve every tool, path and URL request for this session) and
        `show`. Otherwise the command is not available.

/resume [{id}]                                          *boomer-/resume*
        Load a saved session for Neovim's current working directory, which
        may differ from the one the agent started in. Without a chat, this
        starts the default agent first; then dismissing the picker, or
        having no saved sessions, starts a new session. Choosing the open
        session keeps it and writes `[Session: {title} (current)]`. Like
        `/new` and `/agent`, it carries the draft over to the new buffer.

/new                                                    *boomer-/new*
        Start a new session with the same agent, in Neovim's current working
        directory.

/agent [{name}]                                         *boomer-/agent*
        Stop the current agent and start {name} in the same windows. This
        also restarts an agent that exited. Choosing the running agent keeps
        it and writes `[Agent: {name} (current)]`. See |boomer-agents|.

/compact [{focus}]                                      *boomer-/compact*
        Summarize the conversation to free context. Codex compacts the
        thread natively, between turns only, and takes no {focus}. ACP
        agents that advertise their own `/compact` get the line, with
        {focus}, as a prompt.

/usage                                                  *boomer-/usage*
        Write context, token and cost usage into the chat. Works during a
        turn. Codex also shows the 5-hour and weekly rate limits (percent
        used and reset time), fetched fresh when signed in with ChatGPT.

/help                                                   *boomer-/help*
        List the available commands, including user and agent commands.

/cancel                                         *boomer-/cancel* *boomer-cancel*
        Cancel the active turn and put the queued prompts back into the
        draft (|boomer-queue|), like CTRL-C in the chat.

/close                                          *boomer-/close* *boomer-close*
        Stop the agent and wipe the chat buffer.

`/new`, `/resume` and `/agent` need an idle chat. If the agent has exited,
they, like plain |:Boomer|, restart it in the same windows, keeping the
draft.

                                                       *boomer-agent-commands*
ACP agents advertise their own slash commands (for example Copilot's
`/plan`). They complete like Boomer's and are sent to the agent as prompt
text. A `/name` that is neither a Boomer, user nor agent command is not sent;
Boomer warns and keeps the draft.

4. CONFIGURATION                                               *boomer-config*

                                                        *boomer.setup()*
Calling `setup()` is optional. Options apply to the next chat; an invalid
option raises an error. Defaults: >lua

    require('boomer').setup({
        -- Profile started by :Boomer.
        agent = 'codex',
        -- Agent profiles, merged with the built-in ones; see |boomer-agents|.
        agents = {},
        -- User slash commands; see |boomer-user-commands|.
        commands = {},
        -- Show the status in the chat's 'winbar': true, false, or a
        -- function(status) returning a 'winbar' string; see |boomer-winbar|.
        winbar = true,
        -- Where the chat opens; see |boomer-window|.
        window = { position = 'right', width = 0.5, height = 0.5, float = {} },
        -- Labels of user and agent messages; the prompt is the user label
        -- followed by a space. A profile's `label` overrides `agent`.
        labels = { prompt = 'Prompt:', agent = 'Agent:' },
        -- Gutter signs of user and agent messages, or false; see
        -- |boomer-signs|.
        signs = { prompt = '▌', agent = '▌' },
        -- Maximum lines of a file change diff, or false for no limit; see
        -- |boomer-diffs|.
        diff_lines = 64,
    })
<
                                                        *boomer-window*
`window` sets how a chat that is not shown opens:

  position      `'right'`, `'left'`, `'top'`, `'bottom'` or `'float'`.
                Splits span the whole editor (like |:botright|).
  width         Width of `left`, `right` and `float` windows.
  height        Height of `top`, `bottom` and `float` windows.
  float         Extra |nvim_open_win()| config for floats, such as
                `border`, `title` or `row` and `col`. The border defaults
                to 'winborder'.

A size below 1 is a fraction of the editor, otherwise a number of cells.
Floats are centered and follow the editor size (|VimResized|). Examples: >lua

    window = { position = 'left', width = 80 }
    window = { position = 'bottom', height = 0.3 }
    window = {
        position = 'float',
        width = 0.8,
        height = 0.8,
        float = { border = 'rounded', title = ' Boomer ' },
    }
<
                                                        *boomer-signs*
`signs` marks every line of a message, and of the draft, with a sign of its
role in the sign column: `prompt` for user messages and `agent` for agent
messages. Signs are 1 or 2 cells wide; tool, permission and status lines get
none. They are drawn by the chat's 'statuscolumn', on every screen row of
wrapped lines, which replaces the sign column ('signcolumn' is `no`) for the
chat buffer only. Set `signs = false` to disable them. >lua

    signs = { prompt = '┃', agent = '│' }
<
                                                        *boomer-user-commands*
`commands` maps a name to a command, or to `false` to disable the built-in
command of that name. User commands override agent commands. A command has
`desc` (for /help and completion), optional `complete` (a list, or a
function(status) returning one) and exactly one of:

- `prompt`: text sent as a prompt. `$ARGUMENTS` is replaced by the
  arguments; without it, arguments are appended after a blank line.
- `run`: function(args, ctx) run in Neovim. Its line is shown as the user's
  message first.

`ctx` has `args`, `buf` (chat buffer), `status` (|boomer.status()|),
`send(text)` (send a prompt like the draft: queued during a turn) and
`write(text)` (write a note into the chat). Once the chat or its session is
replaced (such as by `/new`), `send()` and `write()` do nothing. Example: >lua

    require('boomer').setup({
        commands = {
            review = {
                desc = 'Review the working tree',
                prompt = 'Review `git diff` and list problems. $ARGUMENTS',
            },
            alt = {
                desc = 'Ask about the alternate file',
                run = function(args, ctx)
                    ctx.send('About ' .. vim.fn.bufname('#') .. ': ' .. args)
                end,
            },
            usage = false, -- let the agent handle /usage
        },
    })
<

5. AGENTS                                                      *boomer-agents*

An agent profile names a protocol and the process that speaks it. The agent
runs in Neovim's working directory (|getcwd()|) when the chat starts. Its
sessions use the working directory Neovim has when |boomer-/new| or
|boomer-/resume| runs: after |:cd|, the running agent lists and opens sessions
for the new directory.
Built-in profiles expect the executable on `$PATH`. The Codex profile: >lua

    codex = { protocol = 'codex', command = 'codex', args = {} },
<
The ACP profiles (`protocol = 'acp'`):

  Name          Command and args            Agent
  copilot       `copilot --acp --stdio`       GitHub Copilot CLI
  auggie        `auggie --acp`                Augment Auggie CLI
  claude        `claude-agent-acp`            Claude Agent (Claude Code)
  cline         `cline --acp`                 Cline
  cursor        `cursor-agent acp`            Cursor
  gemini        `gemini --acp`                Gemini CLI
  goose         `goose acp`                   goose
  kimi          `kimi acp`                    Kimi CLI
  kiro          `kiro-cli acp`                Kiro CLI
  opencode      `opencode acp`                OpenCode
  qwen          `qwen --acp`                  Qwen Code
  vibe          `vibe-acp`                    Mistral Vibe

The `/agent` picker and completion list the profiles whose executable is
installed, plus the default and current ones; `:Boomer agent {name}` accepts
any profile.

Fields given in `setup({ agents = ... })` replace the built-in fields of the
same name (`args` is replaced, not appended). Profile fields:

  protocol      `'codex'` or `'acp'` (required for new profiles).
  command       Executable (required for new profiles).
  args          List of arguments. Codex always runs
                `{command} app-server --listen stdio://` followed by `args`.
                ACP agents run `{command} {args}`.
  env           Environment variables added to Neovim's environment.
  model         Model for new sessions (ID or name).
  effort        Reasoning effort for new sessions.
  mode          Mode for new sessions, such as `plan`.
  options       Table of ACP session config option IDs to values, applied
                to new sessions.
  label         Label of the agent's messages, such as `'Copilot:'`;
                defaults to `labels.agent`.

Defaults apply to new sessions only; a loaded session keeps its settings.
ACP agents get them in order: `model`, `effort`, `mode`, then `options`, so
an effort only the chosen model offers works.
A default the agent refuses is reported in the chat. Example: >lua

    require('boomer').setup({
        agent = 'copilot',
        agents = {
            copilot = { model = 'claude-sonnet-4.5', effort = 'high' },
            gemini = {
                command = 'npx',
                args = { '-y', '@google/gemini-cli', '--acp' },
            },
            myagent = { protocol = 'acp', command = 'my-agent' },
        },
    })
<

6. STATUS                                                      *boomer-status*

The chat's 'winbar' shows a `Boomer` title on the left, then the agent, model
and effort, mode, state, queued prompts, context use, cost and Codex rate
limits (5-hour and weekly, as percent used; highlighted from 90%), aligned to
the right, for example: >

    Boomer      copilot | Claude Sonnet 4.5 (high) | Plan | running | ctx 42%
    Boomer       codex | gpt-5 (high) | ready | ctx 42% | 5h 7% | wk 33%
<
In a narrow window the status is truncated from its left; the title stays.
It is set window-locally for the chat buffer only. Set `winbar = false` to
disable it.

                                                        *boomer-winbar*
A function receives the status (|boomer.status()|) and returns a 'winbar'
string; escape `%` in values as `%%`. An error shows an empty winbar. >lua

    winbar = function(st)
        return st.agent .. ' | ' .. st.state .. ' | ' .. (st.title or '')
    end
<
                                                        *boomer.status()*
`require('boomer').status()` returns a copy of the chat's status, or nil
without a chat:

  agent         Profile name.
  protocol      `'codex'` or `'acp'`.
  state         `starting`, `loading`, `ready`, `running`, `cancelling`,
                `no session` (none open, such as after a failed load; use
                `/new` or `/resume`) or `exited` (the agent stopped;
                |:Boomer| restarts it).
  queued        Number of queued prompts (|boomer-queue|), nil when none.
  session       Session ID.
  title         Session title, if the agent names it.
  model, effort, mode
                Current values, as shown to the user.
  permissions   Permission preset label (Codex), such as `Read Only`, or
                `Custom` when the session's policy matches no preset.
  context       `{ used = n, size = n }` tokens in the context window.
  tokens        `{ total = n, input = n, output = n }`: session totals
                (Codex).
  cost          `{ amount = n, currency = s }` (ACP, if reported).
  limits        `{ primary = l, secondary = l }` account rate limits (Codex,
                ChatGPT login), each `{ used = percent, window = minutes,
                resets = unix time }`: usually the 5-hour and weekly windows.
  cwd           Working directory of the session.
  buf           Chat buffer.

Fields are nil until the agent reports them.

                                                        *boomer.statusline()*
`require('boomer').statusline()` returns the status as one line, escaped for
'statusline', or an empty string without a chat. It has the same items as
the default winbar, without the title. For a statusline plugin: >lua

    require('lualine').setup({
        sections = { lualine_x = { require('boomer').statusline } },
    })
<

7. EVENTS                                                      *boomer-events*

Boomer triggers |User| autocommands:

                                                        *BoomerStatus*
BoomerStatus    After the status changed (at most once per event-loop tick).
                `data` is the status table (|boomer.status()|).

                                                        *BoomerTurnDone*
BoomerTurnDone  After a turn ended. `data` has `buf`, and `result` (such as
                `completed` or `cancelled`) or `error` (a message).

Example: >lua

    vim.api.nvim_create_autocmd('User', {
        pattern = 'BoomerTurnDone',
        callback = function(ev)
            vim.notify('Boomer: ' .. (ev.data.result or ev.data.error))
        end,
    })
<

==============================================================================
8. MAPPINGS                                                  *boomer-mappings*

Boomer defines no global mappings. In the chat buffer:

  <CR>          (Insert) Send the draft or run the command; a prompt is
                queued during a turn (|boomer-queue|).
  <S-CR>        (Normal) Send a prompt now: ahead of queued prompts,
                interrupting the active turn (|boomer-queue|). With a blank
                draft, interrupt the turn for the next queued prompt.
  CTRL-C        (Insert, Normal) Cancel the active turn; queued prompts
                return to the draft, like |boomer-/cancel|.
  <S-Tab>       (Insert, Normal, Visual) Switch to the next session mode
                (|boomer-/mode|). With the completion menu open, it selects
                the previous item instead.

Map |:Boomer| commands with |<Cmd>|: >lua

    vim.keymap.set('n', '<Leader>aa', '<Cmd>Boomer<CR>')
    vim.keymap.set('n', '<Leader>am', '<Cmd>Boomer model<CR>')
    vim.keymap.set('n', '<Leader>ac', '<Cmd>Boomer cancel<CR>')
<

9. HIGHLIGHTS                                              *boomer-highlights*

Groups are defined with `default = true`; override them with
|nvim_set_hl()|.

  BoomerUserLabel       User labels ("Prompt:"), including the live prompt's.
                        Bold, in the color of `Function`.
  BoomerAssistantLabel  Agent labels ("Agent:"). Bold, in the color of
                        `String`.
  BoomerUserSign        Signs of user messages and the draft
                        (|boomer-signs|). Links to `BoomerUserLabel`.
  BoomerAssistantSign   Signs of agent messages. Links to
                        `BoomerAssistantLabel`.
  BoomerSystem          Tool, permission and status lines, and diff fences,
                        file headers and cut-off notes. Links to
                        `Comment`.
  BoomerError           Errors. Links to `DiagnosticError`.
  BoomerWarning         Warnings. Links to `DiagnosticWarn`.
  BoomerDiffAdd         Added lines of diffs (|boomer-diffs|), as a line
                        background. Links to |hl-DiffAdd|.
  BoomerDiffDelete      Deleted lines of diffs. Links to |hl-DiffDelete|.
  BoomerDiffText        The changed part of a deleted line and of the added
                        line replacing it. Links to |hl-DiffText|.
  BoomerDiffHunk        `@@` hunk headers of diffs. Links to |hl-DiffChange|.
  BoomerQueued          `Queued:` lines of queued prompts. Links to
                        `Comment`.
  BoomerPromptBusy      The live prompt's label, sign and text while the chat
                        starts, loads a session or runs a turn (a prompt
                        sent then is queued). Links to `BoomerQueued`.
  BoomerWinbar          Winbar text. Links to |hl-WinBar|.
  BoomerWinbarTitle     The `Boomer` title in the winbar. Links to
                        |hl-Title|.
  BoomerWinbarBusy      Busy states in the winbar. Links to
                        `DiagnosticWarn`.
  BoomerWinbarError     `no session`, `exited` and rate limits from 90% in
                        the winbar. Links to `DiagnosticError`.

10. LUA API                                                       *boomer-api*

All functions are in `require('boomer')`. Command functions return true when
the command started, or nil after a warning.

  setup({opts})         See |boomer.setup()|.
  open()                Open or focus the chat; returns its buffer.
  run({line})           Run a |:Boomer| command line, such as `'model gpt-5'`.
  model([{value}]), effort([{value}]), mode([{value}]),
  permissions([{preset}]), resume([{id}]), new(), agent([{name}]),
  compact([{focus}]), usage(), help(), cancel(), close()
                        See |boomer-commands|.
  status()              See |boomer.status()|.
  statusline()          See |boomer.statusline()|.
  winbar()              The chat window's 'winbar' value.
